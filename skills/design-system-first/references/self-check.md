# Self-check before you hand back UI

Answer each honestly. Any "no" means fix it or list it as a gap.

- [ ] Did I read the system (instructions, tokens, components) before writing code?
- [ ] Is every colour, space, radius, shadow, and font a token or a component prop?
- [ ] Are all sizes/variants ones the system documents (icon sizes, button sizes)?
- [ ] Did I reuse an existing pattern where the problem is a known one?
- [ ] Zero `className`/`style` overrides that change look (layout glue with tokens is OK)?
- [ ] Interaction rules respected (no hover-only actions, pointer cursor only on links, visible focus)?
- [ ] Status colours used only for status; brand colours not confusable with success/error?
- [ ] Is every deviation marked `ds-gap` / `ds-allow` and listed in my reply?
- [ ] Did I say what a human still needs to judge (does this solve the problem, tastefully)?
